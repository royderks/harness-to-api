# AI-assisted contributions

Coding agents are welcome. An identifiable operator remains responsible for every submission, including work posted by a bot account. Use a GitHub identity whose operator can respond to review and follow up on defects.

- Disclose the harness or tool, model when known, and what it did. Distinguish code generation from review-only assistance. State unknown versions rather than inventing them.
- The operator must understand the proposed change and be able to explain its behavior, limitations, and verification. An agent may open a draft, but generated claims still require evidence.
- Link the issue and stay within accepted scope. Do not generate a backlog or send bulk speculative PRs. Start with one focused contribution and respond to review before sending more.
- Run checks that exercise the changed behavior. Include reproducible commands and observed results. Do not present fixtures as live-provider tests or generated media as proof that a command ran.
- Use your own compute, provider accounts, and GitHub credentials. Project maintainers do not distribute their harness logins or gateway keys to contributors.
- Keep comments concise and factual. Automated comments must not claim to be a human review or approval. Do not post credentials, private prompts, or raw provider diagnostics.

All models and harnesses follow the same contribution requirements. Prior accepted work does not waive review. Maintainers may restrict abusive automation or close submissions that do not satisfy the requirements, explaining the reason.
